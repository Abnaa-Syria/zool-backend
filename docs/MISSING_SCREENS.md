# ZoolGo — الشاشات الناقصة من التصميم (نبنيها مباشرة في التطبيقات)

**القرار (2026-11-22):** لا ننتظر المصمم. الشاشات الناقصة تُبنى في Flutter مباشرة **بنفس الهوية البصرية** لملف فيجما (`sz5wZeoY4Bz4rOVhnFpkWq`، صفحة "Test Design") ومكوّناته. كل شاشة هنا لها endpoint جاهز (المرجع: `SCREEN_API_MAP.md`).

## 1. الهوية البصرية (من متغيرات فيجما وشاشات التصميم)

| الدور | اللون | الاستخدام في التصميم |
|---|---|---|
| الأساسي (Primary) | **`#9A1B2F`** (Red 500، عنابي) | زر الإجراء الرئيسي (ابحث عن رحلة، الدفع الآن)، شارات الخصم |
| الأساسي الفاتح | `#F5E8EA` (Red 50) | خلفيات تنبيه/خصم خفيفة |
| الثانوي (Secondary) | **`#03442C`** (Green 500، أخضر داكن) | المبالغ، الأيقونات النشطة، التبويب المختار، مؤشرات الخريطة |
| الثانوي الفاتح | `#E6ECEA` (Green 50) | خلفية الرأس، الزر المختار (ذهاب فقط)، رقائق المقاعد |
| النص الأساسي | `#121212` | العناوين والقيم |
| النص الثانوي | `#494E63` / `#858896` | التسميات والأوصاف |
| الحدود والفواصل | `#C7C8CF` / `#EDEDEF` | حدود البطاقات والحقول |
| حالة نجاح / تحذير / خطأ | `#34C759` / `#FF9500` / `#FF3B30` | الشارات والرسائل |
| الخلفية | `#FFFFFF` مع رأس متدرج أخضر فاتح وصورة شفافة (حافلة/مدينة) | |

**القواعد الشكلية:** واجهة RTL عربية؛ بطاقات بيضاء بزوايا ~16 وظل خفيف؛ حقول بإطار رمادي فاتح وزوايا ~12؛ زر رئيسي عرض كامل بزوايا ~12 ولون عنابي؛ زر رجوع دائري أبيض أعلى اليمين؛ شريط سفلي بأربعة تبويبات (الرئيسية، رحلاتي، الإشعارات، المزيد) والمختار باللون الأخضر؛ الأرقام لاتينية؛ الخط وأحجامه من **Text Styles** في فيجما (Dev Mode) — نصدّرها كـ ThemeData مرة واحدة ولا نكتب ألوانًا أو أحجامًا داخل الشاشات.

**تصحيحات على كل الشاشات (من مراجعة التصميم):** بيانات سودانية (مدن السودان، العملة **ج.س** وليس ر.س، رمز الدولة **+249**)؛ صيغة واحدة لأرقام المقاعد كما يرجعها السيرفر؛ **QR** في التذكرة وليس باركود؛ أسماء الشركات متسقة بين الشاشات.

**مكوّنات مشتركة نبنيها أولًا (تُعاد في التطبيقات الثلاثة):** بطاقة الرحلة، خريطة المقاعد (من `layout` + `seats`، مقاعد السيدات بإطار وردي)، عدّاد الحجز المؤقت، بطاقة التذكرة بـ QR، الحالات الفارغة/التحميل/الخطأ، حوار التأكيد، Bottom sheet للاختيار، شارة الحالة.

## 2. تطبيق العميل

| # | الشاشة الناقصة | ما تعرضه / الحالات | الـ API |
|---|---|---|---|
| C1 | **خطوة «اسمك» بعد أول دخول** | حقل الاسم فقط، ثم الرئيسية | `PATCH /customer/me` (عند `isNewCustomer`) |
| C2 | **فلاتر النتائج (Bottom sheet)** | شركات النقل، نطاق السعر، الدرجة، الخدمات، فترات المغادرة؛ زر «عرض N رحلة» | `GET /customer/trips/filters` |
| C3 | **ترتيب النتائج** | موصى به، الأقرب مغادرة، الأقل سعرًا، الأقصر مدة | معامل `sort` |
| C4 | **ذهاب وعودة: اختيار رحلة العودة** | نفس النتائج بعنوان «رحلة العودة» وتاريخ العودة؛ ملخص رحلة الذهاب أعلى الشاشة | `GET /customer/trips` بالمدينتين معكوستين |
| C5 | **بيانات الركاب** | نموذج لكل مقعد: الاسم، الجنس (إلزامي — مقاعد السيدات تقبل «أنثى» فقط)، الجوال والهوية اختياريان؛ «أنا المسافر» يملأ من الملف | جسم `quote` / `bookings` |
| C6 | **المراجعة بساقين** (توسعة 3074:3175) | بطاقتا رحلة (ذهاب/عودة)، الركاب، الخصم، الإجمالي، **اختيار طريقة الدفع: إلكتروني / نقدًا للسائق** مع سبب عدم الإتاحة | `POST /customer/bookings/quote` |
| C7 | **صفحة الدفع / انتظار الدفع** | تعليمات المزوّد، عدّاد مهلة الدفع، «جارٍ التأكد من الدفع…» | `payment.nextAction`، `GET /customer/payments/:id` |
| C8 | **نتيجة الدفع: نجاح / فشل / انتهت المهلة** | نجاح ← عرض التذكرة؛ فشل/انتهاء ← إعادة المحاولة أو اختيار مقاعد جديدة | حالة الـ intent والحجز |
| C9 | **انتهاء الحجز المؤقت** | حوار «انتهت مدة حجز المقاعد» ← رجوع لخريطة المقاعد | `HOLD_EXPIRED` |
| C10 | **تبويب الرحلات الملغاة** في رحلاتي + **حالات فارغة** للتبويبات الأربعة | | `?tab=CANCELLED` |
| C11 | **بطاقة الذهاب والعودة** في رحلاتي | ساقان تحت حجز واحد، كل ساق تُدار وحدها | `group.otherLeg` |
| C12 | **تأكيد الإلغاء** | المبلغ المسترد، الرسوم، الموعد النهائي، الطريقة؛ سبب اختياري | `GET …/cancellation-quote`، `POST …/cancel` |
| C13 | **تعديل الرحلة — اختيار النوع** | «تغيير المقعد» أو «تغيير موعد الرحلة» (مع سبب عدم الإتاحة) | `actions.canChangeSeat/canChangeTrip` |
| C14 | **تغيير المقعد** | خريطة مقاعد نفس الرحلة، اختيار الراكب والمقعد الجديد | `POST …/change-seat` |
| C15 | **تغيير الموعد** | اختيار تاريخ ← رحلات بديلة بفرق السعر ← مقاعد ← ملخص (ادفع الفرق / يُسترد / يُدفع نقدًا) ← تأكيد | `change-options`، `change-quote`، `change` |
| C16 | **شارات حالة التذكرة** | صالحة، صعد، لم يحضر، ملغاة، مُعدّلة | `status`, `boardingStatus` |
| C17 | **«ادفع للسائق» على التذكرة النقدية** | المبلغ المطلوب عند الصعود | `cashToCollectMinor` |
| C18 | **طرق الدفع (توسعة 3074:3017)** | الإلكتروني + النقد مع سبب عدم الأهلية؛ البطاقات المحفوظة لاحقًا | `GET /customer/payments/methods` |
| C19 | **حذف الحساب** | تأكيد مزدوج؛ رسالة إن وُجدت رحلات قادمة | `DELETE /customer/me` (`ACCOUNT_HAS_ACTIVE_BOOKINGS`) |
| C20 | **التحديث الإجباري / الصيانة** | حوار عند إصدار أقدم من المسموح أو وضع الصيانة | `app-config.minVersions`, `features.maintenanceMode`, `PLATFORM_MAINTENANCE` |
| C21 | حذف «تقييمك 4.8» من الملف الشخصي | استبداله بعدد الوجهات | `stats.destinationsCount` |
| C22 | إزالة تبويب البريد من الدخول | الدخول بالجوال فقط، +249 افتراضيًا | |

## 3. تطبيق السائق

| # | الشاشة الناقصة | ما تعرضه / الحالات | الـ API |
|---|---|---|---|
| D1 | **تسجيل الدخول** | الجوال + كود (نفس شكل دخول العميل)؛ رسالة «هذا الرقم غير مسجّل كسائق» | `/driver/auth/*` |
| D2 | **أزرار دورة الرحلة** في تفاصيل الرحلة | «بدء الصعود» ← «الانطلاق» ← «وصلت المحطة» ← «إنهاء الرحلة» حسب `allowedTransitions`، مع تأكيد | `POST …/status`، `POST …/stops/:id` |
| D3 | **نتيجة المسح غير الصالحة** (توسعة 3043:3312) | ألوان وحالات: صالح، صعد سابقًا، رحلة أخرى، ملغاة، رمز غير صالح | `POST …/scan` |
| D4 | **تحصيل النقد عند الصعود** | «حصّل 35,000 ج.س» + تأكيد الاستلام | `cashToCollectMinor` ← `boardings { cashCollectedMinor }` |
| D5 | **الصعود اليدوي** | بحث بالمقعد/الاسم في القائمة ← «تسجيل صعود» بدون QR | `boardings { method: MANUAL }` |
| D6 | **تسجيل عدم الحضور** واتصال بالراكب | زر اتصال (رقم الراكب) و«لم يحضر» | `POST …/no-shows` |
| D7 | **ملخص النقد للرحلة** | المتوقع، المحصّل، المتبقي، قائمة التذاكر النقدية | `GET …/cash` |
| D8 | **حالات فارغة** | لا رحلات اليوم، لا ركاب | |
| D9 | **حالة GPS** | مؤشر «الموقع يُرسَل» / «لا توجد إشارة» مع إرسال المخزّن لاحقًا | `POST …/positions` |
| D10 | توحيد اسم الشركة بين الرئيسية والملف الشخصي | من `GET /driver/me` | |

## 4. تطبيق الوكيل

| # | الشاشة الناقصة | ما تعرضه / الحالات | الـ API |
|---|---|---|---|
| B1 | **تسجيل الدخول** | الجوال + كود | `/broker/auth/*` |
| B2 | **المحفظة والشحن** | الرصيد، السجل، طلب شحن، رفع إيصال، حالة الطلبات | `/broker/wallet/*` |
| B3 | **الرصيد غير كافٍ / تجاوز الحد اليومي / انتهاء الحجز المؤقت** | حوارات أخطاء التأكيد | `INSUFFICIENT_BALANCE`, `EXPOSURE_CEILING_EXCEEDED`, `HOLD_EXPIRED` |
| B4 | **إلغاء الحجز** | تأكيد مع المبلغ العائد للمحفظة والعمولة المستردة | `POST /broker/bookings/:id/cancel` |
| B5 | **تعديل الحجز** | تغيير المقعد / تغيير الرحلة مع أثر المحفظة والعمولة الجديدة | `change-seat`, `change-options`, `change-quote`, `change` |
| B6 | **ذهاب وعودة** | نفس منطق C4 وC6 بمحفظة المكتب | `quote/confirm` مع `returnTrip` |
| B7 | **تصحيح حساب شاشة المراجعة** | الخصم = سعر التذاكر كاملًا؛ العمولة تُكتسب وتُسوّى لاحقًا (لا «صافي خصم») | `POST /broker/bookings/quote` |
| B8 | **تصحيح بطاقة الملف الشخصي** | المكتب والدور وليس «شركة + تقييم» | `GET /broker/auth/me` |
| B9 | **الإشعارات** | سجل + شارة غير مقروء | `/broker/notifications` |

**مرجع عملي للوكيل:** لوحة الوكلاء الويب (`zool-broker-dashboard`) تنفّذ كل هذه المسارات فعليًا — نفس المنطق والنصوص العربية ورسائل الأخطاء.
